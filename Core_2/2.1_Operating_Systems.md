## Windows Editions and Features

### Windows 10 / 11 Editions

| Edition        | Typical Use            | Key Features                                                         |
| -------------- | ---------------------- | -------------------------------------------------------------------- |
| **Home**       | Consumer               | Consumer features; no built-in RDP server or local Group Policy editor      |
| **Pro**        | Business / Power Users | BitLocker, Group Policy, Remote Desktop, Hyper-V, domain join        |
| **Enterprise** | Large organizations    | Builds on Pro; enterprise deployment/licensing options; LTSC availability depends on product |
| **Education**  | Schools                | Similar to Enterprise; licensed for education                        |

> **Exam Tip:** BitLocker, Group Policy, and domain join are **Pro and above** features. If a scenario describes a home user, they likely have Windows Home.

### Windows Lifecycle and Encryption

Ordinary Windows 10 support ended October 14, 2025. ESU enrollment and specific LTSC editions have separate conditions and timelines; check the installed edition/build. Keep Windows 10 knowledge for exam scenarios and legacy support, and use a supported host for new labs. Source: [Microsoft lifecycle notice](https://support.microsoft.com/en-us/windows/deployment/updates-lifecycle/windows-10-support-has-ended-on-october-14-2025).

Distinguish full BitLocker administration from automatic Device Encryption, which can be available on supported Home devices. A TPM is recommended for measured boot protection; BitLocker can use supported non-TPM startup protectors when configured appropriately. Source: [BitLocker FAQ](https://learn.microsoft.com/en-us/windows/security/information-protection/bitlocker/bitlocker-key-management-faq).

### Windows 11 Minimum Requirements (Notable)

- TPM 2.0 (Trusted Platform Module)
- UEFI firmware with Secure Boot capability
- Compatible 64-bit processor/SoC with 2+ cores at 1 GHz+; check Microsoft’s supported processor list
- 4 GB RAM; 64 GB storage
- DirectX 12 compatible GPU with WDDM 2.0 driver; 720p display larger than 9 inches

> Sources: [Windows 11 requirements](https://www.microsoft.com/en-us/windows/windows-11-specifications), [Windows To Go removal](https://learn.microsoft.com/en-gb/previous-versions/windows/it-pro/windows-10/deployment/windows-to-go/windows-to-go-overview), [AppLocker availability](https://learn.microsoft.com/en-us/windows/configuration/lock-down-windows-10-applocker). Windows To Go was removed starting with Windows 10 version 2004. AppLocker availability depends on Windows version and updates, not simply Enterprise edition.

## Windows File System and Disk Management

### File Systems

| File system | Typical purpose | Selection considerations |
| --- | --- | --- |
| FAT32 | Broad compatibility with removable media and firmware | A single file must be smaller than 4 GiB; formatter limits are not the filesystem's theoretical limit |
| exFAT | Large files on removable media | Common Windows/macOS interoperability; lacks NTFS-style permissions/journaling |
| NTFS | Windows system and data volumes | Permissions, journaling and encryption; limits depend on Windows version and cluster size |
| ReFS | Resilient storage on supported Windows products | Integrity/resiliency features; availability and supported uses depend on edition/version |
| ext4 | Linux system and data volumes | Journaling and Unix permissions |
| XFS | Linux data volumes | Journaling; often selected for large files and scalable storage |
| APFS | Modern Apple systems | Supports encryption, snapshots and space sharing |

On modern Windows versions, NTFS can support volumes up to 8 PB with a suitable cluster size; this is not the limit for every configuration. Prioritize choosing a compatible filesystem over memorizing unqualified theoretical maxima. Source: [Microsoft NTFS overview](https://learn.microsoft.com/en-us/windows-server/storage/file-server/ntfs-overview).

### Partition Styles

| Style | Common Windows use | Partition considerations |
| --- | --- | --- |
| MBR | Legacy BIOS boot; commonly limited to about 2 TiB with 512-byte logical sectors | Four primary entries, or three primary plus one extended partition containing logical drives |
| GPT | Modern partitioning; Windows UEFI boot; large data disks | Windows supports up to 128 partitions; data-disk support and OS boot requirements are different |

For Windows UEFI boot, use GPT for the system disk. A GPT data disk does not itself require UEFI boot. Source: [Microsoft large-disk guidance](https://learn.microsoft.com/en-us/troubleshoot/windows-server/backup-and-storage/support-for-hard-disks-exceeding-2-tb).

---

### Disk Types

| Type             | Description                                                    |
| ---------------- | -------------------------------------------------------------- |
| **Basic Disk**   | Standard MBR or GPT disk; single partitions                    |
| **Dynamic Disk** | Supports advanced features: spanned, striped, mirrored volumes |
| **VHD/VHDX**     | Virtual Hard Disk — can be mounted as a real disk              |

### Disk Management Tool

Access: `diskmgmt.msc` or right-click Start → Disk Management

Key tasks:

- Initialize new drives (MBR or GPT)
- Create, format, and delete partitions/volumes
- Assign or change drive letters
- Extend or shrink existing volumes
- Mark an appropriate MBR boot partition Active (not a GPT/UEFI operation)

## Windows Networking Configuration

### Key Settings

| Setting                            | Location                                              |
| ---------------------------------- | ----------------------------------------------------- |
| - IP address / DNS                 | Network adapter properties → IPv4 properties          |
| - Wi-Fi profile                    | Settings → Wi-Fi → Manage known networks              |
| - VPN                              | Settings → Network & Internet → VPN                   |
| - Firewall                         | Windows Defender Firewall (control panel or Settings) |
| - Network profile (Public/Private) | Settings → Network & Internet → connection properties |

> Setting a network to **Private** allows file and printer sharing. **Public** blocks most inbound connections — appropriate for untrusted Wi-Fi.

### Remote Desktop (RDP)

- **Enable:** Settings → System → Remote Desktop → Enable
- **Requirement:** Windows Pro or higher on the **host**; any edition can be the **client**
- **Default port:** 3389 (TCP)
- **Client application:** `mstsc.exe`

### Permissions

Linux permissions use a three-group model: **Owner, Group, Others**

Each group can have: **Read (r=4), Write (w=2), Execute (x=1)**

```
-rwxr-xr--  1  user  group  1024  Jan 1  file.sh
 ↑↑↑                    owner permissions (rwx = 7)
    ↑↑↑                 group permissions (r-x = 5)
       ↑↑↑              others permissions (r-- = 4)
```

| `chmod` Example         | Numeric   | Meaning                                                |
| ----------------------- | --------- | ------------------------------------------------------ |
| `chmod 755 file.sh`     | rwxr-xr-x | Owner: full; Group: read+execute; Others: read+execute |
| `chmod 644 file.txt`    | rw-r--r-- | Owner: read+write; Group: read; Others: read           |
| `chmod 600 private.key` | rw------- | Owner: read+write; No one else                         |

**Ownership:**

```bash
chown username:groupname file.txt   # Change owner and group
chgrp groupname file.txt            # Change group only
```

## OS Installation and Upgrade

### Installation Methods

| Method                    | Description                                                                 |
| ------------------------- | --------------------------------------------------------------------------- |
| **Clean install**         | Format drive and install fresh OS                                           |
| **Upgrade**               | Preserve files and settings while updating to new version                   |
| **In-place repair**       | Re-install OS files without formatting; used to fix corrupted installations |
| **Unattended install**    | Automated installation using an answer file/script                          |
| **Network install (PXE)** | Boot from network; receive OS image from a deployment server                |
| **Image deployment**      | Deploy a pre-configured OS image (Ghost, MDT/SCCM)                          |

### Upgrade Considerations

Before any upgrade or major change:

1. **Back up all data**
2. Verify hardware meets minimum requirements
3. Check application compatibility
4. Ensure sufficient disk space
5. Download drivers for new OS version

## OS Selection, Application Installation and Cloud Productivity

Choose an OS by the application, hardware architecture, support lifecycle and management requirements. ChromeOS commonly supports browser-centered workflows; iOS/iPadOS and Android serve mobile devices with different vendor controls. Cross-platform files, permissions and app formats need compatibility checks.

### Installing an Application

1. Confirm an approved source, valid license, supported OS/CPU architecture and required RAM, storage and dependencies.
2. Check user permissions and organizational deployment policy; use elevation only when needed.
3. Consider effects on other apps, network usage, users and restart/downtime.
4. Install on a test system or create a recovery point as appropriate.
5. Verify launch, updates, licensing and the user's normal workflow. Record the version and outcome.

On Linux, identify the package manager and trusted repository before installing. Configuration files commonly include `/etc/hosts` (local name mappings), `/etc/fstab` (filesystem mounts), `/etc/passwd` (account metadata) and `/etc/shadow` (protected password hashes). DNS settings may be generated by the network manager rather than edited directly in `/etc/resolv.conf`.

### Cloud Productivity Setup

| Step | What to check |
| --- | --- |
| Identity | Correct organization/tenant and user account; use required MFA |
| Entitlement | Assigned subscription/license includes the required desktop or browser tools |
| Installation | Approved client/source, supported OS and correct update channel |
| Connectivity | Reachability, proxy/VPN requirements and service status |
| Synchronization | Correct account, folders, quota, selective-sync and offline settings |
| Sharing | Least-privilege recipient access and organizational policy |
| Verification | Create/edit a harmless test document; confirm sync from another approved client; remove test data when finished |

Examples include Microsoft 365 and Google Workspace. Distinguish sync from backup: a deletion may synchronize to every device, and recovery depends on the service's retention/versioning features. Avoid placing regulated or confidential files in an unapproved personal account.
