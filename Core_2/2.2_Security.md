## Physical Security

Physical security prevents unauthorized persons from accessing hardware, facilities, and sensitive data.

| Control                                | Description                                                                  |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| **Mantrap / Access Control Vestibule** | Double-door airlock; prevents tailgating into a secure area                  |
| **Badge/Key Card Access**              | Electronic access control; generates an audit trail                          |
| **Biometric Access**                   | Fingerprint, retina, or facial recognition for high-security areas           |
| **Security Cameras (CCTV)**            | Deterrence and forensic evidence                                             |
| **Equipment Lock**                     | Cable locks for laptops; locking server racks                                |
| **USB Data Blocker**                   | Allows charging at public USB ports without data transfer (blocks data pins) |
| **Privacy Screen**                     | Limits viewing angle to prevent visual eavesdropping ("shoulder surfing")    |
| **Secure Print**                       | Print jobs held on the printer until the user authenticates at the device    |

> **Tailgating/Piggybacking:** A person follows an authorized individual through a secured door without authenticating. Mantraps physically prevent this. Training addresses it procedurally.

## Logical Security Concepts

### User Account Control (UAC)

- Windows feature that prompts for elevated privileges before admin-level changes are made
- Prevents standard users and malware from silently making system changes
- Levels: Always notify → Default → Notify only for app changes → Never notify (least secure)

### Principle of Least Privilege

Users and applications should have **only the minimum permissions necessary** to perform their function. No more.

### Access Control Models

| Model                      | Description                                             | Example                       |
| -------------------------- | ------------------------------------------------------- | ----------------------------- |
| **DAC (Discretionary AC)** | Resource owner defines permissions                      | Windows NTFS permissions      |
| **MAC (Mandatory AC)**     | System-enforced labels; users cannot change permissions | Government classified systems |
| **RBAC (Role-Based AC)**   | Permissions assigned to roles, users assigned to roles  | AD group membership           |

### Key Security Concepts

| Term                           | Definition                                                               |
| ------------------------------ | ------------------------------------------------------------------------ |
| **AAA**                        | Authentication, Authorization, Accounting                                |
| **Defense in Depth**           | Multiple overlapping security layers; no single point of failure         |
| **Zero Trust**                 | Never trust, always verify; even internal users are untrusted by default |
| **Sandboxing**                 | Running untrusted code in an isolated environment                        |
| **Data-at-rest encryption**    | Encrypting stored data (BitLocker, FileVault)                            |
| **Data-in-transit encryption** | Encrypting data as it travels (TLS, VPN, SSH)                            |

## Wireless Security

| Protocol | Status           | Algorithm  | Notes                                                        |
| -------- | ---------------- | ---------- | ------------------------------------------------------------ |
| **WEP**  | **Deprecated**   | RC4        | Cracked within minutes; never use                            |
| **WPA**  | **Deprecated**   | TKIP       | Improved over WEP but still vulnerable                       |
| **WPA2** | Minimum standard | AES (CCMP) | Personal (PSK) and Enterprise (802.1X) modes                 |
| **WPA3** | **Recommended**  | SAE        | Protects against offline dictionary attacks; forward secrecy |

### WPA2 vs WPA3 Key Differences

| Feature         | WPA2                             | WPA3                                        |
| --------------- | -------------------------------- | ------------------------------------------- |
| Authentication  | Pre-Shared Key (PSK)             | Simultaneous Authentication of Equals (SAE) |
| Offline attacks | Vulnerable to dictionary attacks | Resistant — SAE eliminates offline cracking |
| Forward secrecy | No                               | Yes                                         |
| Open networks   | Unencrypted                      | Opportunistic Wireless Encryption (OWE)     |

### SSID and Wireless Hardening

| Measure                              | Purpose                                                            |
| ------------------------------------ | ------------------------------------------------------------------ |
| Use WPA3 (or WPA2 minimum)           | Encrypt wireless traffic                                           |
| Change default SSID                  | Remove vendor clues that can aid attacks                           |
| **Change default admin credentials** | Critical — default passwords are publicly documented               |
| Disable WPS                          | Wi-Fi Protected Setup is vulnerable to brute-force PIN attacks     |
| Enable MAC filtering                 | Weak control — MAC addresses can be spoofed                        |
| SSID broadcast disable               | Minor obscurity — determined attackers can still find hidden SSIDs |

## Malware Types and Characteristics

| Malware Type                   | Description                                                                       | Key Characteristic                                    |
| ------------------------------ | --------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **Virus**                      | Attaches to and infects legitimate files; requires user action to spread          | Needs a host file                                     |
| **Worm**                       | Self-replicates across networks without user interaction                          | Self-propagating                                      |
| **Trojan**                     | Disguises itself as legitimate software                                           | No self-replication; requires user to run it          |
| **Ransomware**                 | Encrypts user files; demands payment for decryption key                           | Most damaging for businesses                          |
| **Spyware**                    | Secretly collects user data and sends to attacker                                 | Often installed with freeware                         |
| **Adware**                     | Displays unwanted advertisements; may slow system                                 | Usually bundled software                              |
| **Keylogger**                  | Records keystrokes to capture passwords and sensitive data                        | Can be hardware or software                           |
| **Rootkit**                    | Hides itself and other malware from the OS; operates at kernel level              | Very difficult to remove; often requires offline scan |
| **Botnet**                     | Infected machines (bots) controlled remotely by a command-and-control (C2) server | Used for DDoS attacks, spam                           |
| **RAT (Remote Access Trojan)** | Gives attacker full remote control of the infected machine                        | Persistent, stealthy                                  |
| **Fileless Malware**           | Operates entirely in memory; no disk-based files                                  | Evades traditional signature-based AV                 |
| **Cryptominer**                | Uses victim's CPU/GPU resources to mine cryptocurrency                            | Causes high CPU usage and heat                        |

> **v15 Update:** AI-driven malware detection and EDR (Endpoint Detection and Response) tools are introduced in 220-1202 as part of the modern defensive toolkit.

## Malware Removal Procedure

Follow this structured approach for suspected malware infections:

1. **Identify and research malware symptoms**
   - Unexpected pop-ups, slow performance, renamed/encrypted files, unknown processes

2. **Quarantine the infected system**
   - Disconnect from the network to prevent lateral movement or data exfiltration

3. **Disable System Restore** (Windows)
   - System Restore points may contain malware backups

4. **Boot into Safe Mode**
   - Limits running processes; makes malware easier to detect and remove

5. **Run updated anti-malware scans**
   - Use multiple tools (e.g., Windows Defender + Malwarebytes)
   - For rootkits, use an offline/bootable scanner

6. **Remove or quarantine detected malware**
7. **Re-enable System Restore and create a clean restore point**
8. **Update OS and applications** — patch the vulnerability that allowed infection
9. **Educate the user** — explain how the infection occurred
10. **Document the incident**

## Social Engineering Attacks

Social engineering exploits human psychology rather than technical vulnerabilities.

| Attack                        | Description                                                                        |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| **Phishing**                  | Mass fraudulent emails impersonating legitimate organizations to steal credentials |
| **Spear Phishing**            | Targeted phishing tailored to a specific individual using personal details         |
| **Whaling**                   | Phishing targeting senior executives (C-level)                                     |
| **Vishing**                   | Voice phishing — phone calls impersonating IT support, banks, or officials         |
| **Smishing**                  | SMS-based phishing                                                                 |
| **Tailgating / Piggybacking** | Physically following an authorized person through a secure door                    |
| **Shoulder Surfing**          | Watching a user's screen or keyboard to capture credentials                        |
| **Dumpster Diving**           | Searching discarded documents for sensitive information                            |
| **Impersonation**             | Posing as IT support, a vendor, or authority to gain access                        |
| **Evil Twin**                 | A rogue Wi-Fi AP that mimics a legitimate network to intercept traffic             |

> **Defense:** User training is the most effective control against social engineering. Technical controls (spam filters, call screening) are secondary.

## Authentication Methods

### Authentication Factors

| Factor                 | Type                  | Examples                                   |
| ---------------------- | --------------------- | ------------------------------------------ |
| **Something you know** | Knowledge             | Password, PIN, security questions          |
| **Something you have** | Possession            | Smart card, OTP token, authenticator app   |
| **Something you are**  | Inherence / Biometric | Fingerprint, facial recognition, iris scan |
| **Somewhere you are**  | Location              | GPS location, IP-based geofencing          |

### Multi-Factor Authentication (MFA)

MFA requires **two or more different factor types**. (Two passwords = not MFA — same factor type.)

- Password + OTP code (SMS or app) = MFA ✓
- Password + security question = NOT MFA (both are "something you know") ✗

### Single Sign-On (SSO)

Authenticate once and access multiple applications. Common implementations:

- **SAML** — Web-based SSO (often used with cloud apps)
- **Kerberos** — Active Directory SSO (Windows enterprise environments)

### Windows Authentication

| Method                | Description                                           |
| --------------------- | ----------------------------------------------------- |
| **Local account**     | Credentials stored locally on the machine             |
| **Microsoft account** | Cloud-linked; syncs settings and BitLocker keys       |
| **Domain account**    | Authenticated by Active Directory; centrally managed  |
| **Windows Hello**     | Biometric or PIN; replaces password for local sign-in |

## Data Destruction and Disposal

When decommissioning hardware, data must be permanently destroyed to prevent recovery.

| Method                   | Description                                                | Best For                                               |
| ------------------------ | ---------------------------------------------------------- | ------------------------------------------------------ |
| **Overwriting (Wiping)** | Write zeros or random data over all sectors                | HDDs; SSDs (use SSD-specific wipe tools)               |
| **Low-level format**     | Resets drive to factory state; secure but slow             | HDDs                                                   |
| **Degaussing**           | Strong magnetic field destroys data on magnetic media      | HDDs, magnetic tapes; **does NOT work on SSDs**        |
| **Physical destruction** | Shredding, drilling, or incinerating the drive             | Highest security; physically unrecoverable             |
| **Cryptographic erase**  | Destroy the encryption key; data is permanently unreadable | SSDs with hardware encryption; eSSD/NVMe best practice |

> **Exam Tip:** Degaussing does **not** work on SSDs or optical media — they are not magnetically encoded. Physical destruction is the gold standard for high-security environments.

### Compliance Standards for Data Disposal

- **DoD 5220.22-M:** US Department of Defense standard — multiple overwrite passes
- **NIST 800-88:** Current standard recommending cryptographic erase for SSDs

## Endpoint Security Tools

| Tool                                      | Function                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------- |
| **Antivirus / Anti-malware**              | Signature-based detection of known malware                                      |
| **EDR (Endpoint Detection and Response)** | Behavioral analysis and response; detects fileless and zero-day threats         |
| **Host-based Firewall**                   | Controls inbound/outbound traffic on individual devices                         |
| **DLP (Data Loss Prevention)**            | Prevents unauthorized transfer of sensitive data                                |
| **SIEM**                                  | Aggregates and analyzes security logs from multiple sources                     |
| **TPM (Trusted Platform Module)**         | Hardware chip that stores encryption keys; required by BitLocker and Windows 11 |
| **Patch Management**                      | Regularly applying OS and app updates to close known vulnerabilities            |
