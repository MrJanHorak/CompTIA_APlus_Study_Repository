## Physical Security

Physical security prevents unauthorized persons from accessing hardware, facilities, and sensitive data.

| Control                                | Description                                                                  |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| **Mantrap / Access Control Vestibule** | Double-door airlock; prevents tailgating into a secure area                  |
| **Badge/Key Card Access**              | Electronic access control; generates an audit trail                          |
| **Biometric Access**                   | Fingerprint, retina, or facial recognition for high-security areas           |
| **Security Cameras (CCTV)**            | Deterrence and forensic evidence                                             |
| **Equipment Lock**                     | Cable locks for laptops; locking server racks                                |
| **USB Data Blocker**                   | Allows charging at public USB ports without data transfer (blocks data pins) |
| **Privacy Screen**                     | Limits viewing angle to prevent visual eavesdropping ("shoulder surfing")    |
| **Secure Print**                       | Print jobs held on the printer until the user authenticates at the device    |

> **Tailgating/Piggybacking:** A person follows an authorized individual through a secured door without authenticating. Mantraps physically prevent this. Training addresses it procedurally.

## Logical Security Concepts

### User Account Control (UAC)

- Windows feature that prompts for elevated privileges before admin-level changes are made
- Prevents standard users and malware from silently making system changes
- Levels: Always notify → Default → Notify only for app changes → Never notify (least secure)

### Principle of Least Privilege

Users and applications should have **only the minimum permissions necessary** to perform their function. No more.

### Access Control Models

| Model                      | Description                                             | Example                       |
| -------------------------- | ------------------------------------------------------- | ----------------------------- |
| **DAC (Discretionary AC)** | Resource owner defines permissions                      | Windows NTFS permissions      |
| **MAC (Mandatory AC)**     | System-enforced labels; users cannot change permissions | Government classified systems |
| **RBAC (Role-Based AC)**   | Permissions assigned to roles, users assigned to roles  | AD group membership           |

### Key Security Concepts

| Term                           | Definition                                                               |
| ------------------------------ | ------------------------------------------------------------------------ |
| **AAA**                        | Authentication, Authorization, Accounting                                |
| **Defense in Depth**           | Multiple overlapping security layers; no single point of failure         |
| **Zero Trust**                 | Never trust, always verify; even internal users are untrusted by default |
| **Sandboxing**                 | Running untrusted code in an isolated environment                        |
| **Data-at-rest encryption**    | Encrypting stored data (BitLocker, FileVault)                            |
| **Data-in-transit encryption** | Encrypting data as it travels (TLS, VPN, SSH)                            |

## Wireless Security

| Protocol | Status           | Algorithm  | Notes                                                        |
| -------- | ---------------- | ---------- | ------------------------------------------------------------ |
| **WEP**  | **Deprecated**   | RC4        | Cracked within minutes; never use                            |
| **WPA**  | **Deprecated**   | TKIP       | Improved over WEP but still vulnerable                       |
| **WPA2** | Minimum standard | AES (CCMP) | Personal (PSK) and Enterprise (802.1X) modes                 |
| **WPA3** | **Recommended**  | SAE        | Protects against offline dictionary attacks; forward secrecy |

### WPA2 vs WPA3 Key Differences

| Feature         | WPA2                             | WPA3                                        |
| --------------- | -------------------------------- | ------------------------------------------- |
| Authentication  | Pre-Shared Key (PSK)             | Simultaneous Authentication of Equals (SAE) |
| Offline attacks | Vulnerable to dictionary attacks | Resistant — SAE eliminates offline cracking |
| Forward secrecy | No                               | Yes                                         |
| Open networks   | Unencrypted                      | Opportunistic Wireless Encryption (OWE)     |

### SSID and Wireless Hardening

| Measure                              | Purpose                                                            |
| ------------------------------------ | ------------------------------------------------------------------ |
| Use WPA3 (or WPA2 minimum)           | Encrypt wireless traffic                                           |
| Change default SSID                  | Remove vendor clues that can aid attacks                           |
| **Change default admin credentials** | Critical — default passwords are publicly documented               |
| Disable WPS                          | Wi-Fi Protected Setup is vulnerable to brute-force PIN attacks     |
| Enable MAC filtering                 | Weak control — MAC addresses can be spoofed                        |
| SSID broadcast disable               | Minor obscurity — determined attackers can still find hidden SSIDs |

## Malware Types and Characteristics

| Malware Type                   | Description                                                                       | Key Characteristic                                    |
| ------------------------------ | --------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **Virus**                      | Attaches to and infects legitimate files; requires user action to spread          | Needs a host file                                     |
| **Worm**                       | Self-replicates across networks without user interaction                          | Self-propagating                                      |
| **Trojan**                     | Disguises itself as legitimate software                                           | No self-replication; requires user to run it          |
| **Ransomware**                 | Encrypts user files; demands payment for decryption key                           | Most damaging for businesses                          |
| **Spyware**                    | Secretly collects user data and sends to attacker                                 | Often installed with freeware                         |
| **Adware**                     | Displays unwanted advertisements; may slow system                                 | Usually bundled software                              |
| **Keylogger**                  | Records keystrokes to capture passwords and sensitive data                        | Can be hardware or software                           |
| **Rootkit**                    | Hides itself and other malware from the OS; operates at kernel level              | Very difficult to remove; often requires offline scan |
| **Botnet**                     | Infected machines (bots) controlled remotely by a command-and-control (C2) server | Used for DDoS attacks, spam                           |
| **RAT (Remote Access Trojan)** | Gives attacker full remote control of the infected machine                        | Persistent, stealthy                                  |
| **Fileless Malware**           | Operates entirely in memory; no disk-based files                                  | Evades traditional signature-based AV                 |
| **Cryptominer**                | Uses victim's CPU/GPU resources to mine cryptocurrency                            | Causes high CPU usage and heat                        |

> **Scope:** Core 2 objective 2.4 includes EDR, MDR and XDR. AI use, limitations and policy are addressed separately in operational procedures objective 4.10.

## Malware Removal Procedure

Use the workflow in Core 2 objective 2.6 for basic SOHO scenarios. For organizational incidents, follow the incident-response team's containment and evidence-preservation instructions before changing the system.

1. Investigate and confirm symptoms.
2. Quarantine the affected system.
3. Disable System Restore in the Windows Home scenario specified by the objectives.
4. Remediate the infection.
5. Update anti-malware tools using a trusted source.
6. Scan and remove threats, using Safe Mode or a preinstallation environment where appropriate.
7. Reimage/reinstall when required to establish a trusted system.
8. Schedule scans and run updates.
9. Restore System Restore protection and create a clean restore point for the Windows Home scenario.
10. Explain prevention and safe practices to the user.

Record symptoms, actions and outcome in the support ticket. Reconnect only after verifying the system is safe and organizational requirements are satisfied. Source: [CompTIA Core 2 objectives, 2.6](https://lecbyo.files.cmp.optimizely.com/download/cefedfb2b8a511ef809306d06d323538).

## Social Engineering Attacks

Social engineering exploits human psychology rather than technical vulnerabilities.

| Attack                        | Description                                                                        |
| ----------------------------- | ---------------------------------------------------------------------------------- |
| **Phishing**                  | Mass fraudulent emails impersonating legitimate organizations to steal credentials |
| **Spear Phishing**            | Targeted phishing tailored to a specific individual using personal details         |
| **Whaling**                   | Phishing targeting senior executives (C-level)                                     |
| **Vishing**                   | Voice phishing — phone calls impersonating IT support, banks, or officials         |
| **Smishing**                  | SMS-based phishing                                                                 |
| **Tailgating / Piggybacking** | Physically following an authorized person through a secure door                    |
| **Shoulder Surfing**          | Watching a user's screen or keyboard to capture credentials                        |
| **Dumpster Diving**           | Searching discarded documents for sensitive information                            |
| **Impersonation**             | Posing as IT support, a vendor, or authority to gain access                        |
| **Evil Twin**                 | A rogue Wi-Fi AP that mimics a legitimate network to intercept traffic             |

> **Defense:** Combine user training, phishing-resistant authentication, filtering and verification procedures; the appropriate controls depend on the attack and environment.

## Authentication Methods

### Authentication Factors

| Factor                 | Type                  | Examples                                   |
| ---------------------- | --------------------- | ------------------------------------------ |
| **Something you know** | Knowledge             | Password, PIN, security questions          |
| **Something you have** | Possession            | Smart card, OTP token, authenticator app   |
| **Something you are**  | Inherence / Biometric | Fingerprint, facial recognition, iris scan |
| **Somewhere you are**  | Location              | GPS location, IP-based geofencing          |

### Multi-Factor Authentication (MFA)

MFA requires **two or more different factor types**. (Two passwords = not MFA — same factor type.)

- Password + OTP code (SMS or app) = MFA ✓
- Password + security question = NOT MFA (both are "something you know") ✗

### Single Sign-On (SSO)

Authenticate once and access multiple applications. Common implementations:

- **SAML** — Web-based SSO (often used with cloud apps)
- **Kerberos** — Active Directory SSO (Windows enterprise environments)

### Windows Authentication

| Method                | Description                                           |
| --------------------- | ----------------------------------------------------- |
| **Local account**     | Credentials stored locally on the machine             |
| **Microsoft account** | Cloud-linked; syncs settings and BitLocker keys       |
| **Domain account**    | Authenticated by Active Directory; centrally managed  |
| **Windows Hello**     | Biometric or PIN; replaces password for local sign-in |

## Data Destruction and Disposal

Choose a method for the media, data sensitivity and organizational policy; verify the result and record disposal details.

| Method | What to know |
| --- | --- |
| Overwriting | Can clear addressable HDD data when properly performed; inaccessible or remapped areas need consideration |
| Formatting | A quick format or a tool labelled “low-level format” is not a sanitization guarantee |
| Device sanitize / secure erase | Use a supported, media-appropriate command and verify successful completion; SSD wear levelling makes ordinary file overwrites insufficient |
| Cryptographic erase | Makes encrypted data inaccessible by sanitizing the relevant keys, provided implementation and key-management requirements are met |
| Degaussing | Appropriate magnetic-media equipment can sanitize magnetic storage; ineffective for SSDs and optical media |
| Physical destruction | Use an approved process suitable for the medium; a single drilled hole does not ensure all flash chips or platter regions are destroyed |

Source: [NIST SP 800-88 Revision 2, September 2025](https://csrc.nist.gov/pubs/sp/800/88/r2/final). Historical “DoD multi-pass wipe” terminology is not a universal modern requirement. Preserve records and use approved recycling/disposal channels.

| Tool                                      | Function                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------- |

## Windows Permissions and Workstation Hardening

### Accounts and File Access

Use a standard account for daily work and elevation only for approved administrative tasks. Distinguish local accounts from centrally managed domain accounts and groups.

For a shared Windows folder, check **share permissions** and **NTFS permissions**. Network access must pass both; effective rights are limited by their combination. Local filesystem access uses NTFS permissions without the share-permission layer. Group membership, inherited rules and explicit allow/deny entries affect the result; use Effective Access tools rather than relying on a single simplified rule.

Practice in a VM: create a test folder and local test users, grant read access to one group and modify access to another, then verify each account. Do not change production permissions for practice.

### Hardening Checklist

- Keep OS, apps and firmware updated, using an approved supported build.
- Apply least privilege, appropriate screen locks and account-lockout policy.
- Use unique credentials and a password manager; follow the organization's password and MFA policy.
- Disable unused services, guest access and unnecessary startup/autorun behavior.
- Enable appropriate firewall profiles, encryption and endpoint protection.
- Back up recovery keys using approved secure storage and verify recovery procedures.

### Mobile and SOHO Security

Apply device encryption, screen locks, updates, approved apps and MDM configuration profiles. Distinguish BYOD from corporate ownership before remote wipe or data collection; follow policy and authorization.

On a SOHO router, change default administrator credentials, patch firmware, use secure management and restrict remote administration. Separate guest access, allow only needed forwarding rules, and disable unnecessary UPnP. A screened subnet separates exposed services from trusted systems. Hidden SSIDs and MAC filtering do not replace strong authentication and encryption.

## Browser Security

Install browsers and extensions from approved sources; verify signatures or vendor-published hashes when supplied. Keep the browser patched, review extension permissions and remove unneeded extensions.

Check certificate warnings, HTTPS, pop-up permissions, proxy settings, saved credentials and browser sync. Do not bypass certificate warnings to make a work task succeed. Private browsing limits some local history persistence; it does not make the user anonymous to sites, network administrators or service providers.

When troubleshooting, clear only the relevant cache/site data when possible and explain that cookies or saved sessions may be removed. Apply organizational password-manager and content-filtering policies.

## Additional Threats and Detection Services

| Term | Distinction |
| --- | --- |
| MDR | A managed service that performs detection and response work |
| XDR | Correlates detection/response signals across multiple security layers |
| EDR | Focuses on endpoint activity and response |
| Stalkerware | Covert monitoring software; follow escalation and evidence procedures |
| QR-code phishing | A QR code sends the user to a deceptive destination |
| BEC | Business email compromise abuses trusted business communication |
| On-path attack | Intercepts or alters traffic between parties |
| SQL injection / XSS | Untrusted input affects database queries / browser-executed content |
| Supply-chain compromise | A trusted supplier, update or dependency becomes an entry point |

DoS/DDoS attacks disrupt availability; brute-force and dictionary attacks attempt credentials; insider threats originate from trusted access. Unpatched, unsupported or unmanaged devices increase exposure. Detecting a symptom is not proof of the cause: collect evidence and escalate.
