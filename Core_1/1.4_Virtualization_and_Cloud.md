## Virtualization Concepts

**Virtualization** is the process of running a simulated computer environment (virtual machine) on top of a physical host system. A single physical machine can host multiple VMs, each isolated from the others.

### Key Terms

| Term                 | Definition                                                                  |
| -------------------- | --------------------------------------------------------------------------- |
| **Host**             | The physical machine running the hypervisor                                 |
| **Guest**            | The virtual machine (VM) running on the host                                |
| **Hypervisor**       | Software that manages and allocates host resources to VMs                   |
| **Snapshot**         | A saved state of a VM at a specific point in time; used for quick rollbacks |
| **Clone**            | A complete copy of a VM; used for rapid deployment                          |
| **Template**         | A sealed VM image used to create new VMs quickly                            |
| **Virtual NIC**      | A software-simulated network card assigned to a VM                          |
| **Virtual Switch**   | A software switch that manages traffic between VMs and the host             |
| **Resource Pooling** | Sharing CPU, RAM, and storage across multiple VMs                           |

## Hypervisor Types

### Type 1 — Bare-Metal Hypervisor

- Runs **directly on the hardware**, with no host OS required
- The hypervisor _is_ the operating environment
- **Examples:** VMware ESXi, Microsoft Hyper-V (Server), Citrix Hypervisor (XenServer)
- **Use case:** Enterprise data centers, server virtualization
- **Advantages:** Lower overhead, better performance, higher security

### Type 2 — Hosted Hypervisor

- Runs **on top of a conventional host OS** (Windows, macOS, Linux)
- The host OS is running, and the hypervisor runs as an application within it
- **Examples:** VMware Workstation, VirtualBox, Parallels Desktop
- **Use case:** Developer workstations, personal testing, home lab environments
- **Advantages:** Easier to install and use; leverages host OS drivers

> **Exam Tip:** Type 1 = better performance (enterprise). Type 2 = easier to use (personal/testing). The key differentiator is whether there is a host OS underneath the hypervisor.

### Comparison Table

| Feature             | Type 1 (Bare-Metal)  | Type 2 (Hosted)                |
| ------------------- | -------------------- | ------------------------------ |
| Host OS required    | No                   | Yes                            |
| Performance         | Higher               | Lower (more overhead)          |
| Typical environment | Data center / server | Desktop / workstation          |
| Security isolation  | Greater              | Less (shares host OS)          |
| Examples            | ESXi, Hyper-V Server | VirtualBox, VMware Workstation |

## Virtual Machine Components

When creating a VM, these resources are allocated from the host:

| Resource                        | Description                                                                       |
| ------------------------------- | --------------------------------------------------------------------------------- |
| **vCPU**                        | Virtual processors assigned to the VM; supported limits and overcommit depend on the hypervisor         |
| **RAM**                         | Memory allocated to the VM; cannot exceed host's available RAM                    |
| **Storage (VMDK/VHD)**          | Virtual disk file stored on host storage; appears as a physical disk to the guest |
| **Virtual NIC**                 | Network adapter; can be bridged, NAT, or host-only                                |
| **ISO / Virtual Optical Drive** | Mount an OS image to install or boot the guest                                    |

### VM Network Modes

| Mode                 | Behavior                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| **Bridged**          | VM appears as a separate device on the physical network; gets its own IP from DHCP                  |
| **NAT**              | VM shares the host's IP address; can access the internet but is not directly visible on the network |
| **Host-Only**        | Host and VMs on the same host-only network can communicate; no external access by default                                   |
| **Internal Network** | VMs can communicate with each other but not the host or external network                            |

## Cloud Computing Models

### Deployment Models

| Model               | Description                                                                           | Example                                  |
| ------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------- |
| **Public Cloud**    | Resources owned and operated by a third-party provider; shared infrastructure         | AWS, Azure, Google Cloud                 |
| **Private Cloud**   | Cloud infrastructure operated exclusively for one organization; on-premises or hosted | Internal VMware environment              |
| **Hybrid Cloud**    | Combination of public and private; workloads move between them                        | On-prem servers + AWS for burst capacity |
| **Community Cloud** | Shared among organizations with common concerns (e.g., government agencies)           | Federal shared services                  |

### Cloud Characteristics (NIST Definition)

All cloud services share these five essential characteristics:

1. **On-demand self-service** — Provision resources without human interaction with the provider
2. **Broad network access** — Access from any device over the network
3. **Resource pooling** — Multi-tenant infrastructure shared among many customers
4. **Rapid elasticity** — Scale resources up or down quickly
5. **Measured service** — Pay only for what you use (metered billing)

## Cloud Service Models

### IaaS — Infrastructure as a Service

- Provider delivers: **virtualized compute, storage, and networking**
- Customer manages: OS, middleware, applications, data
- **Examples:** AWS EC2, Azure Virtual Machines, Google Compute Engine
- **Use case:** Replace or supplement on-premises servers; full control over the OS

### PaaS — Platform as a Service

- Provider delivers: **hardware + OS + runtime environment**
- Customer manages: their own applications and data only
- **Examples:** AWS Elastic Beanstalk, Azure App Service, Heroku, Google App Engine
- **Use case:** Developers deploy applications without managing server infrastructure

### SaaS — Software as a Service

- Provider delivers: **the complete application**
- Customer manages: only their data and user settings
- **Examples:** Microsoft 365, Google Workspace, Salesforce, Dropbox
- **Use case:** End users consume a ready-to-use application through a web browser

### Comparison Summary

```
IaaS → You manage everything above the hardware
PaaS → You manage the application and data
SaaS → You manage almost nothing
```

> **Memory Aid:** Think of pizza as a service:
>
> - **IaaS** = Grocery store pizza (you bake it yourself)
> - **PaaS** = Delivery pizza (someone makes it; you just eat it at home)
> - **SaaS** = Restaurant pizza (everything is handled for you)

## Client-Side Virtualization Use Cases

For A+ technicians, the relevant virtualization context is primarily **desktop virtualization**:

| Use Case                       | Description                                                                   |
| ------------------------------ | ----------------------------------------------------------------------------- |
| **Testing / Sandboxing**       | Run malware analysis or untrusted software in an isolated VM                  |
| **Development**                | Test applications on different OS versions without multiple physical machines |
| **Legacy application support** | Run old software that requires Windows XP or 7 in a VM on a modern host       |
| **OS cross-training**          | Practice another supported guest OS; verify host architecture and guest licensing                                  |
| **System snapshots**           | Take a snapshot before making system changes; revert if something breaks      |

### Requirements for Client-Side Virtualization

- **Compatible CPU and guest architecture:** Enable Intel VT-x/AMD-V on x86 hosts; Arm hosts require supported Arm guests
- **Sufficient RAM:** Host OS needs its own RAM; each VM requires dedicated allocation
- **Storage:** Virtual disk files can be large; SSDs significantly improve VM performance
- **64-bit host OS:** Required to run 64-bit VMs

## Containers, VDI and Shared Resources

A VM includes a guest OS and virtual hardware. A container normally isolates application processes while sharing its host kernel, so it is lighter to start but does not provide a separate guest kernel. Choose a VM when a separate supported OS/kernel is required. Images, patching, access controls and resource limits matter for both.

**Virtual desktop infrastructure (VDI)** hosts desktops centrally for remote access. A local desktop VM instead runs on the user's machine. Check CPU, memory, storage, network and licensing requirements before deploying either.

Cloud capacity can be shared across tenants or dedicated to one customer. **Elasticity** adjusts capacity with demand; **availability** concerns service continuity. Metering measures consumption but does not mean every cloud purchase has only usage-based charges. File synchronization propagates changes; it is not a substitute for an independent recoverable backup.

Practice: explain whether an isolated test application needs a container, a separate OS VM or a remotely hosted desktop, and identify who patches the OS in IaaS, PaaS and SaaS.
