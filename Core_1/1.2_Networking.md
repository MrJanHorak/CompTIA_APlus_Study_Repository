## The OSI Model

The **Open Systems Interconnection (OSI)** model is a conceptual framework that describes how data travels across a network in seven layers. Use it as supporting context for diagnosing connectivity; this table does not predict exam-question frequency.

| Layer | Number       | Name         | Key Devices / Protocols                       |
| ----- | ------------ | ------------ | --------------------------------------------- |
| 7     | Application  | Application  | HTTP, FTP, DNS, SMTP                          |
| 6     | Presentation | Presentation | SSL/TLS, encryption, compression              |
| 5     | Session      | Session      | NetBIOS, RPC — establishes/maintains sessions |
| 4     | Transport    | Transport    | TCP, UDP — segmentation, flow control         |
| 3     | Network      | Network      | IP, routers — logical addressing and routing  |
| 2     | Data Link    | Data Link    | Ethernet, switches, MAC addresses             |
| 1     | Physical     | Physical     | Cables, hubs, NICs — raw bit transmission     |

**Mnemonic (top-down):** _All People Seem To Need Data Processing_
**Mnemonic (bottom-up):** _Please Do Not Throw Sausage Pizza Away_

## TCP vs UDP

| Feature            | TCP                                   | UDP                                |
| ------------------ | ------------------------------------- | ---------------------------------- |
| **Connection**     | Connection-oriented (3-way handshake) | Connectionless                     |
| **Reliability**    | Ordered byte stream with ACKs/retries; reports connection failure         | No delivery guarantee              |
| **Speed**          | Slower (overhead)                     | Faster (low overhead)              |
| **Use Cases**      | Web (HTTP/S), email, file transfer    | DNS queries, VoIP, streaming, DHCP |
| **Error checking** | Yes                                   | Minimal                            |

## IP Addressing

### IPv4

- **Format:** Four octets separated by dots — e.g., `192.168.1.100`
- **Range per octet:** 0–255
- **Total possible addresses:** ~4.3 billion (exhausted; NAT and private addressing reduce public-address demand)

#### Private (RFC 1918) Ranges

| Reserved block | Address range | Mask for the entire reserved block |
| --- | --- | --- |
| 10.0.0.0/8 | 10.0.0.0–10.255.255.255 | 255.0.0.0 |
| 172.16.0.0/12 | 172.16.0.0–172.31.255.255 | 255.240.0.0 |
| 192.168.0.0/16 | 192.168.0.0–192.168.255.255 | 255.255.0.0 |

These are reserved address blocks, not mandatory masks for every LAN. For example, 192.168.1.0/24 uses 255.255.255.0 and is one subnet within 192.168.0.0/16. Historical class B networks used /16, not /12. Source: [RFC 1918](https://www.rfc-editor.org/info/rfc1918/).

---

#### Special Addresses

| Address           | Purpose                                              |
| ----------------- | ---------------------------------------------------- |
| `127.0.0.1`       | Loopback / localhost — tests the local network stack |
| `169.254.x.x`     | APIPA — assigned automatically when DHCP fails       |
| `0.0.0.0`         | Default route / any address                          |
| `255.255.255.255` | Limited broadcast                                    |

### IPv6

- **Format:** Eight groups of four hex digits — e.g., `2001:0db8:85a3::0000:8a2e:0370:7334`
- **Key features:** 128-bit addressing, no broadcast, built-in IPSec support, auto-configuration (SLAAC)
- **Loopback:** `::1`
- **Link-local prefix:** `fe80::/10`

## Subnetting Basics

A **subnet mask** divides an IP address into the network portion and the host portion.

| CIDR Notation | Subnet Mask     | Hosts per Subnet |
| ------------- | --------------- | ---------------- |
| /24           | 255.255.255.0   | 254              |
| /25           | 255.255.255.128 | 126              |
| /26           | 255.255.255.192 | 62               |
| /27           | 255.255.255.224 | 30               |
| /28           | 255.255.255.240 | 14               |
| /30           | 255.255.255.252 | 2                |

> **Exam Tip:** For the A+ exam, you need to understand subnetting conceptually — identify the network address, broadcast address, and valid host range for a given subnet. You are not required to manually binary-convert addresses at the speed of Network+.

## SOHO Network Configuration

A **Small Office/Home Office (SOHO)** network is a common exam scenario.

### Typical SOHO Components

| Device                          | Function                                                            |
| ------------------------------- | ------------------------------------------------------------------- |
| **Modem**                       | Converts ISP signal (cable, DSL, fiber) to Ethernet                 |
| **Router**                      | Routes traffic between local network and the internet; provides NAT |
| **Switch**                      | Connects multiple wired devices on the local network                |
| **Wireless Access Point (WAP)** | Broadcasts Wi-Fi signal                                             |
| **SOHO Router / Combo unit**    | Modem + router + switch + WAP in one device                         |

### Key Router Configuration Tasks

- **DHCP:** Automatically assigns IP addresses to devices; define the IP pool range
- **DNS:** Point to ISP DNS or public DNS (e.g., 8.8.8.8, 1.1.1.1)
- **Default Gateway:** The router's LAN IP address (commonly `192.168.1.1` or `192.168.0.1`)
- **NAT (Network Address Translation):** Allows multiple devices to share one public IP
- **Port Forwarding:** Directs inbound traffic on a specific port to a specific internal host
- **SSID / Wireless Security:** Name the network; configure WPA3 (preferred) or WPA2
- **Firmware Updates:** Keep router firmware current to patch security vulnerabilities
- **Change Default Credentials:** Always replace the factory admin username and password

## Wireless Technologies

### 802.11 Standards Summary

| Standard            | Band                | Max Speed | Key Feature                  |
| ------------------- | ------------------- | --------- | ---------------------------- |
| 802.11a             | 5 GHz               | 54 Mbps   | First 5 GHz standard         |
| 802.11b             | 2.4 GHz             | 11 Mbps   | First widely adopted         |
| 802.11g             | 2.4 GHz             | 54 Mbps   | Backward compatible with b   |
| 802.11n (Wi-Fi 4)   | 2.4 / 5 GHz         | 600 Mbps  | Introduced MIMO              |
| 802.11ac (Wi-Fi 5)  | 5 GHz               | 6.9 Gbps  | MU-MIMO, beamforming         |
| 802.11ax (Wi-Fi 6)  | 2.4 / 5 GHz         | 9.6 Gbps  | OFDMA, improved efficiency   |
| 802.11ax (Wi-Fi 6E) | 2.4 / 5 / **6 GHz** | 9.6 Gbps  | 6 GHz band — less congestion |

> **v15 Update:** Wi-Fi 6E's 6 GHz band is a key new topic. The 6 GHz band reduces interference and provides more non-overlapping channels in high-density environments (offices, stadiums) but has less wall-penetration than 2.4 GHz.

> Wireless figures are theoretical PHY maxima, not file-transfer speeds. Wi-Fi 5's ~6.9 Gbps maximum assumes eight spatial streams and 160 MHz channels; Wi-Fi 4's 600 Mbps assumes four streams and 40 MHz, and Wi-Fi 6's ~9.6 Gbps assumes eight streams and 160 MHz. Client capabilities, interference and protocol overhead lower throughput. [Cisco reference](https://www.cisco.com/c/dam/global/en_ca/assets/ciscoconnect/2013/assets/docs/wireless-feature-updates-ian-procyk-cisco-connect-2013-toronto.pdf).

---

### Wireless Channels

- **2.4 GHz:** 11 channels (US); only channels 1, 6, and 11 are non-overlapping
- **5 GHz:** Many more non-overlapping channels; shorter effective range
- **6 GHz (Wi-Fi 6E):** Even more non-overlapping channels; best for short-range, high-density use

### Wireless Security Protocols

| Protocol | Status          | Notes                                                                                |
| -------- | --------------- | ------------------------------------------------------------------------------------ |
| WEP      | **Deprecated**  | Easily cracked; do not use                                                           |
| WPA      | **Deprecated**  | Improved over WEP but still vulnerable                                               |
| WPA2     | Current minimum | AES encryption; TKIP is deprecated                                                   |
| **WPA3** | **Recommended** | SAE (Simultaneous Authentication of Equals); resistant to offline dictionary attacks |

## Network Hardware

| Device                    | OSI Layer | Function                                              |
| ------------------------- | --------- | ----------------------------------------------------- |
| **Hub**                   | Layer 1   | Broadcasts all traffic to all ports (legacy; avoid)   |
| **Switch**                | Layer 2   | Forwards frames based on MAC address table            |
| **Router**                | Layer 3   | Routes packets based on IP address                    |
| **Wireless Access Point** | Layer 2   | Extends wired network wirelessly                      |
| **Firewall**              | Layer 3–7 | Filters traffic by rules; can be hardware or software |
| **Load Balancer**         | Layer 4–7 | Distributes traffic across multiple servers           |
| **IDS / IPS**             | Layer 3–7 | Detects (IDS) or blocks (IPS) suspicious traffic      |
| **Proxy Server**          | Layer 7   | Acts as intermediary between clients and internet     |

### NIC (Network Interface Card)

- Every NIC has a **MAC address** (Media Access Control) — a factory-assigned, 48-bit hardware address
- MAC format: `XX:XX:XX:XX:XX:XX` (hex) — first 24 bits = manufacturer OUI, last 24 bits = device identifier
- MAC addresses can be **spoofed** in software (security concern)

## Network Cables and Connectors

### Twisted Pair (Copper)

| Category   | Max Speed          | Max Distance | Notes                                       |
| ---------- | ------------------ | ------------ | ------------------------------------------- |
| Cat 5      | 100 Mbps           | 100 m        | Legacy                                      |
| **Cat 5e** | 1 Gbps             | 100 m        | Reduced crosstalk; common in older installs |
| **Cat 6**  | 1 Gbps / 10 Gbps\* | 100 m / 55 m | \*10 Gbps at shorter distance               |
| Cat 6a     | 10 Gbps            | 100 m        | Augmented; shielded variants available      |
| Cat 7      | 10 Gbps            | 100 m        | Shielded; proprietary connectors            |

**Connector:** RJ-45 (8P8C) for Ethernet

**Wiring Standards:**

- **T568A / T568B:** Two standard wiring configurations. Within a single installation, use the same standard consistently.
- **Straight-through:** Same standard on both ends — connects unlike devices (PC to switch)
- **Crossover:** Different standards on each end — connects like devices (switch to switch)

> **Note:** Most modern NICs and switches support **Auto-MDI/MDI-X**, which automatically detects cable type, making crossover cables largely obsolete in current deployments.

### Fiber Optic

| Type                  | Core Size     | Use Case                                             |
| --------------------- | ------------- | ---------------------------------------------------- |
| **Single-Mode (SMF)** | 8–10 µm       | Long distance (up to tens of km); laser light source |
| **Multi-Mode (MMF)**  | 50 or 62.5 µm | Short distance (up to ~550 m); LED light source      |

**Connectors:** ST (bayonet), SC (push-pull), LC (small form factor — most common in modern installs)

### Coaxial

| Type  | Use                                 |
| ----- | ----------------------------------- |
| RG-6  | Cable TV, cable modem internet      |
| RG-59 | Legacy CCTV; shorter runs than RG-6 |

**Connectors:** F-type (screw-on for cable TV/internet)

## VPN Technologies

A **VPN (Virtual Private Network)** creates an encrypted tunnel between a client and a network over the public internet.

| Type                  | Description                                                       |
| --------------------- | ----------------------------------------------------------------- |
| **Remote Access VPN** | Individual user connects to the corporate network                 |
| **Site-to-Site VPN**  | Two office networks are permanently connected                     |
| **Split Tunneling**   | Only corporate traffic uses the VPN; internet traffic bypasses it |
| **Full Tunneling**    | All traffic routes through the VPN                                |

**Common VPN Protocols:**

| Protocol    | Port         | Notes                                                                |
| ----------- | ------------ | -------------------------------------------------------------------- |
| IPSec       | UDP 500/4500 | Strong encryption; used in many enterprise VPNs                      |
| SSL/TLS VPN | TCP 443      | Browser-accessible; uses HTTPS port — often not blocked by firewalls |
| OpenVPN     | UDP 1194     | Open-source; highly configurable                                     |
| L2TP/IPSec  | UDP 1701     | Often paired with IPSec for encryption                               |

## DNS, DHCP and Network Services

### DNS Records and Email Authentication

| Record/control | Purpose | Example or distinction |
| --- | --- | --- |
| A | Maps a name to an IPv4 address | web.example.test → 192.168.1.10 |
| AAAA | Maps a name to an IPv6 address | The IPv6 counterpart to A |
| CNAME | Aliases one DNS name to another | An alias points to a name, not directly to an IP |
| MX | Identifies a domain's mail exchangers | Includes a priority/preference value |
| TXT | Publishes text used by many verification systems | Often carries SPF or domain-verification data |
| SPF | Identifies authorized sending systems for the envelope-sender domain | It does not digitally sign each message |
| DKIM | Adds a verifiable signature using a domain's published public key | Detects changes to signed portions |
| DMARC | Checks alignment with the visible From domain and publishes policy/reporting preferences | A message can pass through aligned SPF or DKIM |

Use `nslookup` or `dig` to inspect records. An existing DNS record is different from the client's ability to reach the DNS server. Practice this distinction in [Lab 02](../Labs/Lab_02_Network_Simulation.md).

### DHCP Allocation

A **scope/pool** defines assignable addresses and network options. A **lease** grants temporary use. A **reservation** consistently assigns an address to a client identifier; an **exclusion** keeps addresses out of dynamic allocation. Prevent collisions by excluding statically assigned addresses. Review address, mask, gateway and DNS together when diagnosing failed access.

### Host Services and Appliances

DNS resolves names; DHCP supplies client configuration; file/print servers share resources; mail, web and database servers provide their named applications. NTP synchronizes time and syslog centralizes event messages. AAA separates identity verification, permission decisions and activity accounting.

An email gateway filters mail; a UTM combines security functions; a load balancer distributes requests; a proxy mediates application access. SCADA controls/monitors industrial processes, and IoT/embedded equipment may have limited patching and management features. Inventory and segment such systems according to policy.

## Network Tools, Power and Connections

| Item | Use or troubleshooting check |
| --- | --- |
| Crimper | Terminates suitable modular connectors; match connector and cable |
| Punchdown tool | Seats conductors into patch-panel/keystone contacts |
| Cable tester | Checks wire map, continuity and faults; capabilities vary |
| Tone generator/probe | Traces the intended cable; use equipment rated for the circuit |
| Loopback plug | Helps isolate interface operation; does not prove the whole path |
| Wi-Fi analyzer | Observes channel use and signal conditions |
| Network tap | Gives authorized access to traffic for analysis |
| PoE switch/injector | Supplies power with Ethernet data; match device needs and available power budget |
| ONT | Terminates an optical ISP connection; differs from a cable/DSL modem |

PoE examples include 802.3af (Type 1), 802.3at (Type 2) and 802.3bt (Types 3/4). Power available at the powered device is lower than the supplying port's rating; check both specifications rather than assuming any PoE port powers any device.

Compare cable, DSL, fiber, cellular, fixed wireless/WISP and satellite by availability, bandwidth, latency and reliability. LAN/WLAN describe local wired/wireless networks; WAN spans sites, PAN serves a person's nearby devices, MAN covers a metropolitan area, and SAN provides storage networking.

For RFID, distinguish radio-based identification tags/readers from NFC's very short-range interactions. Both are separate from Wi-Fi network access.
